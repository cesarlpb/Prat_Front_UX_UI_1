# Hoja de ruta para la coordinación del Trabajo Final

## 1. Propósito

Esta guía sirve para que el equipo alinee expectativas, defina responsabilidades y organice sus entregables desde la **primera sesión** hasta la entrega final.

## 2. Dinámica de la primera sesión (Kick‑off)

1. **Presentación rápida** de cada miembro y sus fortalezas.
2. **Lluvia de ideas de posibles proyectos** → votación rápida (método dot‑voting).
3. **Elección del proyecto** y consenso sobre el **Título provisional**.
4. **Redacción colaborativa** de la **Descripción del proyecto** (problema, solución y público objetivo en ≤ 150 palabras).
5. **Creación del tablero** (GitHub Projects, Trello, Jira o equivalente) con estas columnas iniciales:

   * Backlog
   * En curso
   * Revisión / QA
   * Hecho
  
6. **Configuración del repositorio** en GitHub (privado/público) con:

   * README.md (breve)
   * LICENSE (si aplica)
   * ".gitignore" apropiado
7. **Asignación de roles iniciales** (pueden rotar):

   * *Project Lead / Scrum Master*
   * *Tech Lead*
   * *QA & Documentación*
   * *UX/UI*
  
8. **Calendario de stand‑ups** (diarios o cada 48 h) y **demo/revisión** semanal.

## 3. Entregables mínimos obligatorios

* [x] **Título del proyecto**
* [x] **Descripción del proyecto**
* [x] **Tablero de trabajo para el proyecto**
* [x] **Repositorio para el proyecto**

## 4. Entregables recomendados (añaden calidad y evitan fricciones)

* [ ] **Roles y responsabilidades** documentados (tabla RACI ligera).
* [ ] **Cronograma macro** con hitos y fechas clave.
* [ ] **Definición de Hecho (Definition of Done)** para historias y entregables.
* [ ] **Historias de usuario / requisitos funcionales** en el tablero.
* [ ] **Guía de estilo** de código y convenciones de commits.
* [ ] **Plan de comunicación** (canales, tiempos de respuesta, idioma).
* [ ] **Documentación de instalación y despliegue** (archivo INSTALL.md o sección en README).
* [ ] **Métricas de éxito** (KPIs o criterios de evaluación).

## 5. Fases sugeridas

| Fase                     | Duración    | Entregables clave                                            |               |
| ------------------------ | ----------- | ------------------------------------------------------------ | ------------- |
| **Descubrimiento**       | 1 semana    | Benchmark, definición de alcance, prototipo de bajo desgaste |               |
| **Planificación**        | 2‑3 días    | Roadmap detallado, backlog priorizado                        |               |
| **Desarrollo iterativo** | 3‑4 sprints | Incrementos funcionales, demos                               | > QA continuo |
| **Cierre & entrega**     | 1 semana    | Presentación final, retrospectiva, documentación completa    |               |

## 6. Herramientas útiles

* **Gestión de código**: Git + GitHub / GitLab
* **Tablero ágil**: GitHub Projects, Trello, Jira
* **Comunicación**: Slack, Discord, Microsoft Teams
* **Documentación**: Notion, Confluence, HackMD (o .md en el repo)
* **Diseño colaborativo**: Figma, Miro

## 7. Buenas prácticas

* Commits pequeños y descriptivos.
* Pull Requests ligadas a issues y revisadas por al menos 1 compañero/a.
* Integración continua (CI) desde el principio.
* Reuniones cortas y orientadas a objetivos; documentar decisiones clave.
* Revisar el tablero antes de cerrar cada sesión.

## 8. Retrospectiva<br>

Al final de cada sprint, dedicar 15 min a identificar **Qué fue bien**, **Qué podría mejorar** y **Acciones para el próximo sprint**.
